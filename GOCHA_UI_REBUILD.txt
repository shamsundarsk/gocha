GOCHA — UI REBUILD & LOCATION MISSION SYSTEM
============================================
Date: 2026-11-25
Scope: mobile app UI/UX rebuild + location-locked outdoor missions + Day Wrapped redesign
Backend: unchanged

This document explains what was rebuilt, why it was rebuilt that way, how the
location missions work, how each requirement is covered, how to run and test the
app, and what is intentionally demo-only.


1. THE SHORT VERSION
--------------------
Gocha now opens on a live map of the user's location. Outdoor tasks (runs,
walks, gym trips, errands, etc.) become "missions": Gocha pins a finish line on
the map, draws the geofence, and keeps the in-app camera locked until the user
physically reaches that zone. Reaching the pin unlocks a full-screen camera.
The captured photo becomes the proof of the moment, completes the task, and
shows up in Day Wrapped.

The home screen is no longer a list of cards. It is built around four emotional
widgets — Momentum, Move, Nudge and Capture — that motivate, activate, tease and
then lead the user down the photo path.

Day Wrapped was rebuilt as a real end-of-day story: a hero completion ring, a
mood score, meaningful stats, captured moments, what worked, what to try
tomorrow, and a merged timeline of backend events plus on-device photos.


2. DESIGN SYSTEM
----------------
All screens now share one visual language in mobile/src/constants/theme.ts.

Palette
- Background: near-black navy (#07070F), elevated cards (#181828)
- Brand: violet (#7C6AF6) with a light lavender secondary (#B4A5FF)
- Accents: teal (#2DD4BF), amber (#F5A524), rose (#FB7185), sky (#38BDF8)
- Emotion colors:
  spark  = #A78BFA  (momentum)
  move   = #2DD4BF  (movement)
  nudge  = #FB923C  (teasing)
  snap   = #38BDF8  (photo / proof)
- Text: warm white (#F4F2FF), secondary (#9A9DB8), muted (#4B4F66)

Shape, depth and type
- Radii from 6 to 34, with pill radii for chips and CTAs
- Soft black shadows plus a violet "brand" glow for primary actions
- 8-point spacing scale
- Large black display headings, small uppercase eyebrow labels with wide
  letter-spacing, and muted supporting copy
- Gradient tokens for hero cards, brand cards and each emotion tone
- Haptics on emotional widget presses and on camera capture/success

The result is deliberately calm and dark, with color used only for meaning:
violet = the system/brand, teal = progress/arrival, amber = warning, rose =
friction, sky = the photo/proof layer.

- Quick-add composer: natural language input ("run 5k", "walk 20 minutes",
  "buy groceries") that calls the existing parser and creates tasks.
- Suggestion chips, today's schedule timeline (with mission lock pills),
  pending-task fallback cards, nearby event teaser, and a Wrapped teaser with

4. LOCATION MISSIONS — HOW THEY WORK
------------------------------------
Detection (mobile/src/store/missionStore.ts)
- A task is treated as outdoor when:
  - the backend sets is_outdoor, or
  - the title/location contains words such as run, jog, walk, cycle, hike, park,
    gym, market, store, groceries, pickup, drop, coffee, cafe, outside, trail,
    track, or
  - the category is fitness or errands.
- Completed/cancelled/abandoned tasks are not turned into new missions.

Destination generation
- Destinations are deterministic per task: the hash of task id + title +
  category picks a place template (riverside trail, sports track, hill loop,
  park, cafe, market, gym, lake promenade) and a bearing.
- The mission is placed 280-1800 m from the user's current location, using the
  haversine/destination-point math in mobile/src/utils/geo.ts.
- This makes demo missions stable across reloads while still being near the
  user. It is not a real POI lookup.

Geofence
- Unlock radius: 130 m by default, 180 m for market/errand missions.
- The mission records the starting distance so progress can be shown as a
  percentage of the way to the zone.
- The map draws the radius as a dashed circle scaled correctly for the current
  zoom (radius / metres-per-pixel, clamped for readability).

Persistence
- Missions are stored in the app documents folder as gocha-missions.json.
- Captured photos are copied to documents/moments/<taskId>-<timestamp>.jpg and
  the URI is stored on the mission.
- Dismissed/reset task ids are remembered so a reset mission does not come back
  automatically.
- Missions and photos survive app restarts. They do not survive uninstalling
  the app or clearing app data.

States
- LOCKED: mission exists, user is outside the radius.
- READY: user is inside the radius; the camera CTA unlocks.
- DONE: a photo has been captured; the task is completed.

Demo arrival
- Simulators and reviewers can bypass GPS with "Demo arrival" on the mission
  or capture screen. This is clearly labelled as demo-only.
- If the camera cannot mount (simulator), a demo frame can be used to exercise
  the save/complete/wrapped flow.


5. EMOTIONAL WIDGETS — INTENT AND COPY
--------------------------------------
Momentum (violet / spark)
- Shows completion percentage and changes its message as the day progresses:
  fresh page, started, building, on a roll.
- Purpose: motivation without shame.

Move (teal / move)
- Compares steps to a 6,000-step goal (or active minutes to 30).
- Copy moves from "your body wants a lap" to "body: thanked you".
- Purpose: activation. Tapping pre-fills a 20-minute walk request.

Nudge (orange / nudge)
- A rotating set of playful, slightly teasing lines ("Your running shoes just
  filed a missing person report", "You have 2% battery and 80% excuses").
- The daily starting line is deterministic, and tapping cycles to another.
- Purpose: mischief and a push without a guilt trip.

Capture (sky / snap)
- The bridge from emotion to action. It reflects the real mission state:
  no mission -> invite to create one; out of range -> distance to the photo;
  in range -> "You are in range. Take the shot."; completed -> "Moment
  captured."
- Tapping goes straight to the mission or camera, which is the required photo
  path.

All four cards use their emotion gradient, progress bars where relevant, and
light haptic feedback on press.


6. DAY WRAPPED — WHY IT MAKES SENSE
-----------------------------------
The old wrapped screen was generic. The new one answers three questions:

1. What did I actually do?
   - Completion ring, tasks done, focus minutes, distance/steps, active minutes,
     moments captured.
2. How did the day feel?
   - A 0-100 mood score weighted as:
       completion 50%, focus 20%, movement 20%, moments 10%,
       minus up to 25 points for high recreational screen time.
   - Five states with distinct colors and copy, from RESET DAY to LOCKED IN.
3. What should I change tomorrow?
   - "What worked" and "Try tomorrow" are generated from the same numbers
     (e.g. postponed tasks -> reschedule; high screen time -> one phone-free
     block; overplanning -> shrink the list).
   - The timeline merges backend events with the user's actual captured photos,
     so the story includes real proof, not just task records.

The date strip lets the user revisit any of the last seven days. Sharing produces
a readable text summary instead of a generic "look at my stats" message.

9. HOW TO RUN AND TEST
----------------------
0. The app is auth-gated. Start the backend on port 8000 (docker-compose from
   the repo root, or the existing local backend setup), then register or sign in
   in the app. The API base URL is derived from the Expo/Metro host automatically
   (mobile/src/constants/index.ts), so a physical device must be on the same
   network as the backend machine.

1. Install dependencies if needed:
     cd mobile
     npm install

2. Type check:
     npx tsc --noEmit

3. Start the app:
     npx expo start -c
   Use a physical device for the real camera and real GPS. Expo Go supports
   expo-camera, expo-location, expo-file-system and react-native-svg in SDK 51.

4. Grant location permission. Home should show the dark map, a pulsing user pin
   and the city chip.

5. Add an outdoor task in the composer, for example:
     Run 5k in the park
   or tap the "Run 5k" suggestion. A mission is created automatically and the
   map overlay switches to the locked mission panel.

6. Tap the mission panel. Check:
   - destination pin and dashed geofence on the map
   - route line from you to the pin
   - "Navigate to ..." opens walking directions in the native maps app
   - "Path to the photo" progress updates as you move

7. On a simulator (or to test quickly), tap "Demo: simulate arrival" on the
   mission screen, or "Demo arrival" on the camera screen.

8. In the camera:
   - deny/allow camera permission and confirm the permission states
   - if the simulator camera cannot mount, use "Demo frame"
   - take a photo, review it, tap "Use photo"
   - confirm the success toast, task completion, and return to the mission

9. Check Home: the Capture widget should now say the moment is captured, and
   the task should be complete. Open Wrapped: the photo should appear in the
   Moments strip and in the day timeline.

10. Restart the app and confirm the mission and photo still exist.

11. Test Day Wrapped date switching, share, Insights, Discover categories,
    Today timeline/list toggle, and Profile settings.

Expected verification results
- npx tsc --noEmit: passes with no errors.
- npx expo export --platform ios: bundles successfully (validated during this
  rebuild; 4.5 MB Hermes bundle).


10. KNOWN LIMITATIONS / DEMO NOTES
----------------------------------
- Missions are frontend-only. The backend Task model has latitude/longitude
  columns, but the current API schemas do not expose them, so destinations are
  generated deterministically near the user rather than read from the backend.
  If those fields are exposed later, buildMission can prefer them.
- Generated place names (Riverside Trail, City Sports Track, etc.) are templates,
  not real POIs. They are stable per task but not a map search result.
- No turn-by-turn routing inside Gocha. Navigation opens the native maps app in
  walking mode.
- Geofence accuracy depends on device GPS. A 130 m radius is intentionally
  forgiving for urban drift; indoor use can still be unreliable.
- Photos are stored on-device only (documents/moments). They are not uploaded to
  the backend. Clearing app data or uninstalling removes them.
- Photo capture completes the mission locally and then calls the existing task
  status API. If that API call fails (offline/backend down), the moment is still
  saved and shown in Wrapped, but the backend task may remain pending until a
  later successful status update.
- Demo arrival and the demo frame exist so the flow can be reviewed on a
  simulator. They are labelled as demo actions.
- CARTO dark tiles require network access. Without network the map falls back to
  a stylized road grid, and the pins/route/geofence still render.
- Location watching runs while the app is open. There is no background location
  tracking.
- Share uses the native share sheet with a text summary, not a rendered image
  card.
- Day Wrapped still depends on the existing backend wrapped endpoint for
  planned/completed/focus/screen-time/steps data. Local photos are merged in on
  the client.
- The backend, API contracts and database were not modified.
